# Day 1 reflections

## Challenge 1: Minutes to hours
137 / 60 gives 2.2833..., a decimal fraction of an hour. I need whole
hours and leftover minutes, so I use Math. Floor for hours and % for the remainder.

## Challenge 2: Grade labels
The invalid check comes first. Otherwise grade Label(150) would return "A"
because 150 >= 90 is true.

## Challenge 3: Fizz Buzz
The combined check (3 and 5) comes first because 15 is a multiple of both.
If "multiple of 3" came first, 15 would become "Fizz".

## Challenge 4: Discounted cart tax
Tax is calculated after the line discounts, so the customer is taxed on
the price they actually pay.

## Other notes
- type of null returns "object". This is a known JavaScript quirk.
- 0.1 * 3 gives 0.30000000000000004, so I use to Fixed(2) when showing money.
- get Discounted Total returns null for invalid input so the caller can tell
  "no valid result" apart from a real total of 0.

# Day 2 reflections

## Block 1: arrays and object records

- A task is an object with id, title, completed and priority. I keep
  several of them in an array (sample Tasks).
- add Task, complete Task, delete Task and rename Task do not change the
  original array. They return a new one, using the spread operator
  [...tasks] and { ...task }, map and filter.
- Invalid requests: a blank title or an unknown id returns the list
  unchanged. I chose this so the caller always gets a valid array back
  and nothing crashes.
- add Task gives the new task an id of the highest current id + 1, so ids
  stay unique even after a delete.

## Challenge 5: Immutable toggle

toggle Task uses map and copies the matching task with the spread
operator, flipping completed with !task. Completed. Proof: after
toggling task 2, toggled[1].completed is false but
sample Tasks[1].completed is still true, so the original was not
mutated. An unknown id (99) returns all five tasks unchanged.

## Block 2: array methods

- filter keeps matching items, map transforms each item, find returns
  the first match, some/every answer yes/no, reduce builds one result.
- In reduce, the accumulator starts as an empty object {}. For each
  completed task I add 1 to the count for its priority, then return the
  object so the next task can use it.
- Named variables like open Tasks make each step easier to read and debug
  than one long chain.

## Challenge 6: Purchase summary

- An empty list returns total 0, count 0, average 0 and most Expensive
  null, so there is no crash and no division by zero.
- On a tie, the first item wins, because I only replace the best item
  when a price is strictly greater.
- A single item works: it is both the total and the most expensive.

## Block 3: object-oriented programming

- Task is a class. The constructor sets id, title and priority and
  rejects a blank title. Each new Task(...) is an instance.
- completed is a private field (#completed). Code outside the class
  cannot change it directly, only through complete() and toggle().
  This keeps the state predictable, because every change goes through
  methods that I control.
- Task List owns a private #tasks array and exposes add, remove,
  find By Id and get Open Tasks. It has no console or screen code, so the
  same class can be reused with any interface later.

## Challenge 7: Inheritance and composition

- Inheritance version: Reminder extends Task, adds due Date, and
  overrides describe() using super. Describe() plus the due date.
- Composition version: a plain Task sits beside a separate reminder
  object holding the due Date.
- Decision: for this app I choose composition (or just an optional
  due Date field). A due date is one extra piece of optional data, not
  a different kind of task, so a subclass is not warranted. Inheritance
  would make every reminder a Task permanently, which is rigid and adds
  complexity without a benefit here.
## Challenge 8: Task statistics

- completion Rate is 0 for an empty list to avoid dividing by zero.
- open is total minus completed, so total = completed + open always holds.
- by Priority uses reduce with an object accumulator; the counts sum to
  the total, which I checked in the console.
